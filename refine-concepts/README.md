# 精修页 · 让用户强烈感知价值的四个方案

更新：2026-09-08。这组文件独立于 `muse-app.html`，当前结果页 → 精修页（工具 + Auto）保持不动，作为基线。

打开方式：本地起服务后访问 `refine-concepts/index.html` 四台手机并排；点方案名进单页放大看。每页右侧可换四张不同问题的测试照片（发闷 / 逆光 / 偏平 / 偏蓝），三个方案的建议值和文案会跟着照片变。

## 问题拆解

用户从结果页进精修，之所以"感觉不到值"，通常不是工具不够，而是三件事没发生：

1. 没有在第一秒看到"变好了"。工具面板要求用户先动手，价值被推迟。
2. 不知道 App 做了什么。哪怕修好了，看不出差别就等于没修。
3. 没有一个"揭示时刻"。前后对比藏在一个按住才出现的小按钮里。

四个方案分别用不同的方式把这三件事放到台前。它们不是互斥的四个页面，更像四种"谁先动手、怎么揭示"的策略。

## 四个方案一览

| | A 先见成果 | B 成片流 | C 修图建议卡 | D 三步引导 |
| --- | --- | --- | --- | --- |
| 谁先动手 | App | App（给 6 个结果） | App，并解释为什么 | 用户，在 App 的建议值上 |
| 价值时刻 | 进场 1.4 秒光线扫过，照片直接变成修后 | 从原图往左一翻，整张变成完成品 | 三张建议卡逐条亮起，照片同步变，分数 68 → 91 | 每步滑杆自动滑到建议值；最后拖分割线 |
| 保存前最少动作 | 0 | 1 次滑动 | 0 | 3 次 Next（或 Skip all） |
| 用户学到什么 | 改了哪三处 | 六种成片风格 | 这张照片的具体问题 | 三个维度怎么影响照片 |
| 适合 | 高频用户、拍完就发；默认路径 | 内容创作者；可做成片包付费 | 不确定该修什么的用户；建立专业信任 | 首次使用；建立"我会修"的信心 |
| 主要风险 | "被修过头"感 | 6 张都不喜欢就没出路 | 打分让人不适；信息量大 | 老用户嫌慢 |
| 化解 | 三行清单逐项可关、按住看原图 | 第 0 张永远是原图；强度滑杆 | 分数明确是对光线/色彩/清晰度，不是对人 | 顶栏 Skip all 直达结果 |

## 各方案细节

### A · 先见成果（`A-reveal.html`）

进场先显示原图，650 ms 后一条亮线从左向右扫过，扫过的部分变成修后。扫完出现标题"Refined for you"和三行"改了什么"：

- 每行 = 图标 + 名称 + 一句为什么（"Soft-focus on the face only. Texture stays."）+ 右侧勾
- 点一行即关掉该项，照片重算；全关时标题变"Back to your original"
- 右上 Before / After 分段切换，右下按住看原图
- Fine-tune 打开一张小面板：Strength 总强度 + 四根滑杆（Smooth skin / Face light / Warmth / Contrast），滑杆动了清单也跟着更新

三行内容来自对照片的快速读取（面部亮度、面部冷暖、整体对比），不是固定文案。偏暗照片是"Face light lifted"，偏蓝照片是"Skin warmed · Takes the blue out of the skin"。

### B · 成片流（`B-finishes.html`）

没有工具。一叠 300 × 470 的卡片横向 snap 滑动，第 0 张是原图，之后 6 张成片：Clean（照片自适应的 Auto）、Soft Film、Golden、Editorial、Night Glow、Fresh。卡片全出血、底部大字写名称，像一张打印好的成片。下面是描述、成分标签（"Even skin · Face light · Balanced color"）、一根强度滑杆、"Use Golden"主按钮和按住看原图。

进场时卡片会轻轻晃一下并显示"Swipe →"，滑过一次即消失。

### C · 修图建议卡（`C-coach.html`）

进场先扫描 1.4 秒（扫描线 + 四角框），然后：

1. 右上出现"Photo quality 68"环形分数
2. 三张建议卡依次滑入，每张带局部对比小图（皮肤和光线裁到面部，色彩用全图）、问题标题（"Face is a touch dark"）、修法（"Lift the light on the face · +70"）、开关
3. 三个开关依次自动打开，每打开一个照片重算、分数上涨（68 → 75 → 84 → 91）
4. 结束后状态行写"Fixed 3 of 3. Tap a switch to undo one."

任何开关可单独关掉。"Adjust by hand"打开与 A 相同的四滑杆面板。

### D · 三步引导（`D-steps.html`）

顶栏是三段进度条。每步一根加粗滑杆：Skin（0–100）→ Light（0–100）→ Color（−50–+50，中点是原样）。进入每步时滑杆从 0 自动滑到建议值（650 ms），刻度上标着"Suggested"，用户看着照片跟着变。按住看"这一步之前"，前面几步保留。

三步走完进入结果：照片变成可拖动的前后分割视图，下面三个小卡写"Skin +45 · Light +70 · Color −10"，Save 保存，Start over 重来。Skip all 直接用三个建议值出结果。

## 推荐

把 A 作为精修页的默认进场，把其余三个当作 A 的层次，而不是并列的四个页面：

- **A 的进场动效 + 三行清单**替代现在进精修就看到工具面板。用户先被"变好了"接住，工具退到 Fine-tune 后面。这是对"感知价值"贡献最大的一处改动，也最便宜。
- **C 的"为什么"文案**并进 A 的三行清单（已经这样做了）。分数环可以作为 A/B 实验的变量单独测，不必一开始就上。
- **B 的成片**放在 A 之后作为第二层："Refined for you"下面再给一行成片缩略图（Soft Film / Golden / Editorial …），想要风格的人继续往下走，不想的人直接保存。这和现在结果页的"Finishing touches"是同一个位置的升级。
- **D 只给首次用户**。第一次进精修走三步，让用户理解皮肤 / 光线 / 色彩三个维度分别做什么；第二次起直接进 A。

如果只能选一个先上线：A。

## 怎么验证

结果页 → 精修 的入口点击率是前提指标，四个方案在精修页内部比较：

- 进入精修后 10 秒内保存率（A、C 应最高）
- 保存前的操作次数（越少越好，但 D 的目标不是最少）
- 三行清单 / 三个开关的关闭率，按项拆开看：哪一项经常被关，说明默认值过头
- 按住看原图的使用率：太低说明用户没在比较，太高说明对结果没信心
- B：各成片被选中的分布，以及停在原图直接保存的比例
- D：Skip 率按步拆开；第二次进入时 Skip all 的比例
- 精修后 7 日回访是否高于未精修

## 没做但值得考虑的方向

- **成片视频**：把 A 的扫光动效或 D 的分割线导出成 2 秒前后对比视频，直接分享。反差视频本身是社交货币，也是最强的"看得见的价值"。
- **发布场景预览**：把修后照片放进朋友圈九宫格 / Instagram 帖子的框里看，让用户看到"发出去是什么样"。
- **社会证明**：在成片或建议卡上写"82% 的人保留了这一项"。数据够了以后再考虑。
- **付费点**：B 的成片可以按包售卖；C 的"Adjust by hand"以及更多建议卡可以是会员能力。

## 文件与实现边界

```
refine-concepts/
  index.html      四方案并排，可换照片
  A-reveal.html   方案 A
  B-finishes.html 方案 B
  C-coach.html    方案 C
  D-steps.html    方案 D
  shared.css      手机框、暗色主题、通用组件
  shared.js       渲染管线、照片读取（analyse）、建议生成（suggest）、滑杆 / 按住 / 分割等交互
  README.md       本文
```

渲染全部是 Canvas 近似：磨皮是限制在面部区域的软焦叠加，面部提亮是以人像上中部为中心的径向叠加，没有人脸检测。"面部区域"按画面 (50%, 38%) 处、半径 42% 估算，对常规人像成立，横构图或多人照会偏。照片读取只算面部区域平均亮度、冷暖和整体对比三个数。正式实现需要换成人像分割和真正的画质评估，四个方案的交互结构不受影响。
